# Перенос обработчика загрузок на ВМ — чтобы не зависеть от ноутбука

Сейчас загруженные публикации обрабатывает скрипт на ноутбуке. Файлы при этом **не теряются**
(лежат в Object Storage со статусом `queued`), но пока ноутбук выключен — результата нет.
Эта инструкция переносит **тот же самый скрипт** на ВМ, где он работает круглосуточно. Код не меняется.

---

## 1. Что просить у администраторов облака

Нужна одна небольшая ВМ в каталоге `<идентификатор каталога — см. .secrets>` (зона `ru-central1-a`):

| Параметр | Значение | Почему так |
|---|---|---|
| ОС | **Ubuntu 22.04 LTS** | инструкция под неё |
| vCPU | **2**, доля 20–50 % | нагрузка редкая: рендер страниц в JPEG |
| RAM | **4 ГБ** (минимум 2 ГБ) | пиково держит кусок PDF на 40 страниц |
| Диск | **20 ГБ** SSD | сами файлы не хранятся, только ОС и Python |
| Сеть | публичный IP (или NAT) | нужен исходящий доступ к Vision, AI Studio, Object Storage, Nominatim |
| Прерываемая | **можно да** | служба сама поднимается после перезапуска, очередь не теряется |

Формулировка для заявки:
> Прошу небольшую ВМ (Ubuntu 22.04, 2 vCPU 20 %, 4 ГБ RAM, 20 ГБ SSD, публичный IP) в каталоге
> `<идентификатор каталога — см. .secrets>` для фонового сервиса обработки загружаемых пользователями публикаций
> (проект «Цифровой атлас геологических разрезов и палеоархивов»).

**Стоимость** — порядка нескольких сотен рублей в месяц; прерываемая ВМ заметно дешевле.
Точную сумму лучше посчитать в калькуляторе Yandex Cloud.

---

## 2. Что положить на ВМ

Всего три файла (плюс необязательный кэш геокодера):

| Файл | Зачем |
|---|---|
| `.secrets` | ключи: `YANDEX_FOLDER_ID`, `YANDEX_API_KEY`, `BUCKET`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` |
| `52_extract_v2.py` | движок извлечения (обработчик импортирует его) |
| `57_process_uploads.py` | сам обработчик |
| `geocache_sections.json` | *(необязательно)* готовый кэш геокодера — меньше запросов к Nominatim |

Архив публикаций на ВМ **не нужен**: загруженные файлы обработчик берёт из Object Storage.

---

## 3. Установка (один присест, ~15 минут)

```bash
# на своей машине — скопировать файлы
scp .secrets 52_extract_v2.py 57_process_uploads.py geocache_sections.json vm_bootstrap.sh <user>@<ip>:/tmp/

# на ВМ
sudo mkdir -p /opt/loess/pipeline
sudo mv /tmp/.secrets /tmp/52_extract_v2.py /tmp/57_process_uploads.py /opt/loess/pipeline/
sudo mv /tmp/geocache_sections.json /opt/loess/pipeline/ 2>/dev/null || true
sudo bash /tmp/vm_bootstrap.sh
```

`vm_bootstrap.sh` ставит Python-зависимости (`boto3`, `PyMuPDF`, `img2pdf`, `Pillow`),
создаёт службу `loess-ingest` и запускает её в дежурном режиме (`WATCH=1` — опрос очереди раз в 30 с).

---

## 4. Проверка

```bash
systemctl status loess-ingest        # должно быть active (running)
journalctl -u loess-ingest -f        # живой лог обработки
```

Затем загрузи любой PDF через `upload.html` — в логе появится путь задачи, а на странице
статус сменится `в очереди → обработка → готово`.

---

## 5. Эксплуатация

| Действие | Команда |
|---|---|
| Логи | `journalctl -u loess-ingest -f` |
| Перезапуск | `sudo systemctl restart loess-ingest` |
| Остановить | `sudo systemctl stop loess-ingest` |
| Обновить код | скопировать новый `57_process_uploads.py` / `52_extract_v2.py` → `sudo systemctl restart loess-ingest` |

Служба перезапускается сама (`Restart=always`) и переживает перезагрузку ВМ.
Незавершённые задачи остаются в очереди и подхватываются после старта.

---

## 6. Что остаётся делать вручную

Перенос **принятых** объектов на карту (`58_merge_approved.py`) специально оставлен локальным:
он меняет данные карты, и это должно происходить осознанно, с пересборкой и проверкой.

```bash
python 58_merge_approved.py          # принятые -> records_clean_geo_v2.xlsx
python build_customer_map_v2.py      # пересборка карты
python deploy_site.py                # публикация
```

---

## 7. Безопасность

- `.secrets` на ВМ — права `600` (ставит скрипт), в репозиторий не попадает.
- Ключи те же, что у облачных функций; при компрометации меняются в консоли и на ВМ.
- Служба работает от системного пользователя, входящих портов не открывает — наружу ВМ ничего не публикует.
