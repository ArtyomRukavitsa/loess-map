# Деплой публикации карты (fn_publish) — облачный аналог 61_publish.py

Переносит проверенные объекты на карту **без участия ноутбука**: сливает принятые предложения,
досчитывает только новое, пересобирает карту и выкладывает её.

## Почему это быстро

Данные карты живут в бакете (`data/`), а не на чьей-то машине. Полный пересчёт корпуса не делается:
привязка страниц качает OCR только затронутых публикаций, сканы рендерятся только новые,
высоты и радиусы считаются только для новых координат.

Замер на реальном объекте: **54 секунды** (локальный `61_publish.py` тратил ~4 минуты, из них
3.5 минуты — полный пересчёт привязки страниц).

## 1. Подготовить данные (один раз, с локальной машины)

```bash
python 62_sync_data.py up      # отправить таблицу, шаблон и служебные JSON в s3://loess-results/data/
python 62_sync_data.py list    # проверить, что всё на месте
```

Дальше источником правды становится бакет. Забрать актуальное состояние к себе:
`python 62_sync_data.py down`.

## 2. Сборщик карты — из бакета, не из пакета

Класть `builder.py` в пакет функции **не нужно**: `62_sync_data.py up` заливает сборщик
(`build_customer_map_v2.py`) в бакет как `data/builder.py`, и функция берёт его оттуда.
Шаблон карты — там же (`data/template.html`).

Благодаря этому правка сборщика или шаблона **не требует передеплоя функции** — достаточно
повторить `python 62_sync_data.py up`.

(Если файл всё же положить в пакет, функция предпочтёт его — это удобно для отладки.)

## 3. Создать функцию

| Параметр | Значение |
|---|---|
| Имя | `fn-publish` |
| Среда выполнения | **`python311`** |

## 4. Переменные окружения

| Переменная | Значение |
|---|---|
| `BUCKET` | `loess-results` |
| `SITE_BUCKET` | `loess-map` |
| `AWS_ACCESS_KEY_ID` | из `.secrets` |
| `AWS_SECRET_ACCESS_KEY` | из `.secrets` |
| `VERIFY_API` | `https://functions.yandexcloud.net/d4evhi01uh5faspidt74` |

Необязательная: `MIN_KEEP` (по умолчанию `0.9`) — защита от порчи данных: если маркеров стало
меньше 90 % от прежнего, карта не публикуется.

## 5. Вызов

```bash
# опубликовать принятое
curl -X POST "https://functions.yandexcloud.net/<ID>" -H "Content-Type: application/json" -d '{}'

# посчитать, но не выкладывать (полезно для проверки)
curl -X POST "https://functions.yandexcloud.net/<ID>" -H "Content-Type: application/json" -d '{"dry":true}'

# пересобрать карту, даже если новых объектов нет
curl -X POST "https://functions.yandexcloud.net/<ID>" -H "Content-Type: application/json" -d '{"force":true}'
```

Ответ: `{"added": N, "markers": M, "published": true|false, "sec": T}`.
Если принятых объектов нет — функция ничего не делает и сообщает об этом.

## 6. Как запускать

Два варианта, оба рабочие:

- **По кнопке** (рекомендуется) — сделать публичной и вызывать со страницы проверки.
  Карта заказчика тогда пересобирается осознанно, по решению человека.
- **По таймеру** — триггер раз в час. Публичный доступ не нужен.
  Полностью автономно, но карта меняется без ведома человека.

Публичный доступ включай **только** если выбираешь вариант с кнопкой.
